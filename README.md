# Sigryx

**Self-hosted key and signing infrastructure for application backends.**

Sigryx is a Go service for keeping deterministic key-root material encrypted at rest, reconstructing sensitive runtime state only after an explicit N-of-N unseal ceremony, deriving application wallets without persisting child private keys, and providing authenticated signing/verification APIs with auditability and recovery tooling.

> Sigryx is security-sensitive infrastructure. Read the security model and production guidance before using it with valuable keys.

## Current capabilities

- `UNINITIALIZED -> SEALED -> UNSEALED` Vault lifecycle.
- N-of-N owner-held unseal credentials.
- Runtime Vault Encryption Key derived only after successful unseal.
- Protected-memory secret handling and explicit secret destruction.
- Encrypted HD key roots; plaintext root seeds are never returned by the API.
- Deterministic Ethereum-compatible wallets using BIP32/secp256k1 and BIP44 paths.
- No persisted or returned child private keys.
- Ethereum legacy and EIP-1559 transaction signing/verification.
- EIP-712 typed-data signing/verification.
- Domain-separated generic JSON/RAW signing/verification.
- Integrity-field signing backed by encrypted append-only signing records.
- JWT user authentication, rotating refresh tokens, service accounts, RBAC and CIDR restrictions.
- Audit events with configurable normal/critical retention.
- Root-admin key-root recovery export/import.
- Generated OpenAPI and a live interactive REST API client.

The current implementation should not be assumed to provide HSM-backed roots, distributed/quorum signing, or an intent-aware policy engine unless those capabilities are present in the release you are running.

### Live REST API client

Every running Sigryx HTTP server also serves an interactive HTTP REST API client at:

```text
http://<sigryx-host>:<port>/docs
```

The live OpenAPI document is available at:

```text
http://<sigryx-host>:<port>/openapi.json
```

For a default local process:

```text
http://localhost:8080/docs
http://localhost:8080/openapi.json
```

The repository documentation explains architecture and operational behavior; the server-side `/docs` client reflects the concrete Huma REST contract generated by the running build.

## Quick local start

The current `go.mod` declares Go `1.26.5`.

Start the local PostgreSQL dependency:

```bash
make infra-up
```

Create local configuration:

```bash
cp .example.env .env
```

Set the required values described in the [configuration documentation](./docs/src/content/docs/operations/configuration.md), apply migrations, and start the server:

```bash
make migrate-up
make run-server
```

Check it:

```bash
curl -sS http://localhost:8080/v1/health
```

Then open:

```text
http://localhost:8080/docs
```

For the complete bootstrap/unseal/wallet/signing flow, follow [`docs/src/content/docs/usage.md`](./docs/src/content/docs/usage.md).

## Vault model in one paragraph

During initialization, Sigryx creates N unseal slots. Each slot combines an owner-held secret with persisted server-side material to unwrap one real unseal key. Sigryx becomes unsealed only after **all N** slots have been submitted. It then derives the runtime Vault Encryption Key as the SHA-256 digest of the ordered unseal keys. That key exists only in protected runtime memory while unsealed and is destroyed on seal/shutdown. Persistent key-root seeds and signing-record payloads are encrypted under key material derived from this lifecycle; child wallet private keys are derived transiently and are not persisted or returned.

See [Seal & unseal](./docs/src/content/docs/concepts/seal-unseal.md).

## GitHub Pages docs

The repository includes a GitHub Actions workflow that builds `docs/` and publishes `docs/dist/` to GitHub Pages after documentation changes reach `main`.

In the GitHub repository settings, configure **Pages -> Build and deployment -> Source -> GitHub Actions**.

The checked-in defaults target the project-site form:

```text
https://rajabinekoo.github.io/sigryx/
```

Forks and custom domains can override `SIGRYX_DOCS_SITE` and `SIGRYX_DOCS_BASE` or update `docs/astro.config.mjs`.
